# Architecture Decision Records

Короткие записи о принятых архитектурных решениях: контекст, решение, последствия,
отвергнутые варианты. Каждый ADR описывает решение, которое уже действует в коде —
это не план на будущее, а фиксация того, почему система устроена именно так, для
диплома и для будущих участников проекта.

| ADR | Тема | Статус |
| --- | --- | --- |
| [ADR-001](ADR-001-sensor-response-mode.md) | Режим сенсора: шлюз или хост | Принято |
| [ADR-002](ADR-002-clickhouse-storage.md) | Телеметрийное хранилище — ClickHouse | Принято |
| [ADR-003](ADR-003-otlp-transport.md) | Транспорт — OTLP через Kafka | Принято |
| [ADR-004](ADR-004-ml-scope-and-success-criteria.md) | Объём ML и критерии успеха | Черновик, часть критериев не подтверждена |
| [ADR-005](ADR-005-response-model.md) | Модель реагирования | Принято |
| [ADR-006](ADR-006-rejected-alternatives.md) | Отвергнутые направления (P2P, honeypot, sandbox) | Принято |

Новый ADR добавляется файлом `ADR-0NN-краткое-название.md` по тому же шаблону
(Контекст / Решение / Последствия / Отвергнутые варианты) и строкой в таблице выше.
